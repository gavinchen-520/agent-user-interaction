# agent-user-interaction 场景测试提示词

> 用途：把每条提示词原样输入 opencode，触发大模型临时生成 HTML UI 页面并完成交互，用于验证「智能体 + MCP 数据 → 临时页面 → 交互 → 抛弃」的定位与能力边界。
>
> 使用方式：复制「提示词」代码块整段发给 opencode；若需固定端口/磁盘模式，先按 `manual-test-cases.md` 顶部配置启动。

---

## A. 数据处置与审批类

### 场景 1：云资源处置
**提示词**
```
你是云运维助手。假设你已通过 MCP 查询到 6 台闲置服务器（IP、规格、CPU 使用率、最近使用时间等数据你自行虚构即可）。
请生成一个可交互的 HTML 页面，让我对每台服务器选择「保留」或「释放」，支持一键全选释放，
我确认后把最终处置结果回传给你。你收到结果后，请复述我选择的处置清单，后续执行操作等我指令。
```
**验证点**：表格勾选 + 单次提交；提交 `data` 结构完整；模型只依据回传数据复述。
**预期 UI**：带复选框的表格、全选开关、单个提交按钮。

### 场景 2：数据库慢查询处置
**提示词**
```
你是 DBA 助手。假设 MCP 返回了 8 条慢查询（SQL 摘要、耗时、扫描行数、调用方），
请生成一个页面让我逐条选择处置方式：「忽略 / 加索引 / 限流 / 下线」，并附一条可选的全局备注。
我提交后你把每条的处置方式汇总成一个可执行的计划（只生成计划文本，不要执行）。
```
**验证点**：每行独立单选 + 额外文本输入；`kind`/`data` 携带分类结果。
**预期 UI**：每行下拉或单选组 + 底部备注输入框 + 提交按钮。

### 场景 3：报销审批
**提示词**
```
你是财务审批助手。有一笔差旅报销申请（金额、行程、票据摘要你自行虚构，总金额分 4 项明细），
请生成一个审批页面，展示费用明细，让我选择「通过 / 驳回」，若驳回需填写原因，
并允许我修改某几项的报销金额。提交后你复述最终审批结果与金额差异。
```
**验证点**：混合控件（单选 + 文本 + 数字输入）单次提交；金额数据原样回传。
**预期 UI**：明细表 + 每项可编辑金额 + 通过/驳回 + 驳回原因框。

## B. 多步骤交互类

### 场景 4：合同条款审查（三阶段）
**提示词**
```
你是合同审查助手。请分三步帮我审查一份采购合同（条款内容你自行虚构）：
第一步展示合同全文让我确认；第二步针对风险条款（至少 3 条）各给 2 个修改建议让我选择；
第三步把选定建议汇总成修改后的条款草稿让我最终确认。每一步都用一个新的交互页面呈现。
```
**验证点**：多阶段 + `update_html_session` 版本递增；旧页面提交被 STALE 拒绝。
**预期 UI**：3 个连续页面，内容随步骤替换。

### 场景 5：发布前检查清单
**提示词**
```
你是发布负责人助手。请生成一个发布前检查清单页面，包含 8 项检查（代码冻结、测试通过、
监控就绪、回滚方案等，内容自拟），每项带「通过 / 跳过 / 未通过」，未通过需备注原因，
全部勾完后才允许点「开始发布」。提交后你告诉我哪些项未通过以及是否阻断发布。
```
**验证点**：条件启用的提交按钮（全部完成才能提交）；数据完整性。
**预期 UI**：清单 + 状态选择 + 条件解锁的提交按钮。

### 场景 6：入职信息收集（分页表单）
**提示词**
```
你是 HR 助手。请生成一个分 3 页的入职信息收集表单：第 1 页基本信息（姓名/邮箱/电话），
第 2 页教育背景，第 3 页紧急联系人。分页间要有「上一步/下一步」，最后一页提交全部数据。
我提交后你把收集到的结构化信息原样展示给我确认。
```
**验证点**：单页面内多步骤（前端 JS 分页，非多 session）；提交数据聚合完整。
**预期 UI**：单页内的分步表单，底部导航，末页统一提交。

## C. 富媒体与可视化类

### 场景 7：UI 方案视觉对比
**提示词**
```
你是 UI 评审助手。我有 4 个登录页视觉方案需要选择，请用 shell 生成几张占位图片
（可用 SVG 或用程序画出不同配色/布局），把它们嵌入一个可交互 HTML 页面，
以图片网格形式展示，让我单选最满意的一个并附一句评语。提交后你告诉我我的选择与评语。
```
**验证点**：文件模式 / 富媒体渲染（`img-src data: blob:`）；视觉选择交互。
**预期 UI**：多图网格 + 单选高亮 + 评语输入框。

### 场景 8：数据图表可视化
**提示词**
```
你是数据分析助手。假设 MCP 返回了某产品近 12 个月的多维度指标（收入、活跃用户、
订单量，数值自拟），请用 SVG 或 Canvas 在页面里画一个折线图，并提供一个维度切换控件
让我切换要显示的指标，再加一个时间范围滑块。我确认后你回传我当前选中的指标与时间范围。
```
**验证点**：内联 SVG/Canvas 无外部资源；控件与图表联动；回传当前交互状态。
**预期 UI**：自绘图表 + 切换控件 + 滑块 + 提交按钮。

### 场景 9：代码 Diff 逐处审阅
**提示词**
```
你是代码审查助手。假设有一个 PR 包含 6 处改动（改动内容自拟，用着色展示增删行），
请生成一个 diff 审阅页面，让我对每一处改动「通过 / 需修改」，需修改的附意见。
我提交后你把审阅结论汇总成 review 评论列表。
```
**验证点**：着色文本渲染；逐条分类 + 意见；`data` 携带 6 条结构化结论。
**预期 UI**：diff 区块列表 + 每处通过/需修改 + 意见框。

## D. 复杂控件与配置类

### 场景 10：模型参数调优
**提示词**
```
你是算法调优助手。请生成一个参数调节页面，包含：温度（0-2 的滑块）、top_p（0-1 滑块）、
最大 token（数字输入）、是否开启流式（开关）、以及一个预设方案下拉（保守/平衡/激进）。
我调整并提交后，你把我选择的参数组合生成一段模型调用的配置 JSON。
```
**验证点**：滑块/开关/数字/下拉组合控件；数值边界；回传后生成结构化配置。
**预期 UI**：多类型控件面板 + 实时数值显示 + 提交按钮。

### 场景 11：权限矩阵配置
**提示词**
```
你是系统管理员助手。请生成一个权限矩阵页面：行是 5 个角色（管理员/编辑/作者/访客/审计），
列是 8 个操作（读/写/删除/导出/审批/发布/管理用户/查看审计），用复选框矩阵让我配置，
支持按行/按列一键全选，并展示每个角色已勾选的操作数。提交后你回传完整矩阵。
```
**验证点**：二维复选框矩阵 + 全选联动；`data` 携带矩阵结构。
**预期 UI**：矩阵表格 + 行/列全选 + 计数 + 提交按钮。

### 场景 12：故障修复方案选择
**提示词**
```
你是 SRE 助手。线上出现一个故障（现象与告警自拟），请生成一个诊断页面：
顶部展示故障现象与影响面，下面给出 3 个修复方案（各含风险等级、回滚成本、预计耗时），
让我选择其一，并允许填写额外备注。提交后你基于我选的方案生成一份执行步骤说明（不实际执行）。
```
**验证点**：决策对比卡片 + 单选 + 备注；回传后模型生成后续计划。
**预期 UI**：方案卡片对比 + 单选 + 备注 + 提交按钮。

## 能力边界覆盖对照

| 场景 | 覆盖的能力边界 |
|---|---|
| 1、2 | 表格勾选、MCP 数据回传、单次提交 |
| 3 | 混合控件（单选/文本/数字）、金额数据原样 |
| 4 | 多 session 阶段递进、`update_html_session` 版本递增、STALE 拒绝 |
| 5 | 条件解锁提交按钮 |
| 6 | 单页内 JS 分页、数据聚合 |
| 7 | 富媒体/文件模式、`img-src data: blob:` |
| 8 | 内联 SVG/Canvas、无外部资源 |
| 9 | 着色渲染、逐条结构化结论 |
| 10 | 滑块/开关/下拉/数字组合、数值边界 |
| 11 | 二维矩阵 + 全选联动 |
| 12 | 决策卡片 + 执行计划生成 |
